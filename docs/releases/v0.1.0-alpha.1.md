# VoiceBridge v0.1.0-alpha.1 (draft release notes)

> **Alpha. Not production-ready.** This is a first public preview for feedback. APIs, package
> names, and the `/v0` wire contract will change. Nothing is published to npm.

VoiceBridge is open-source middleware for adding a real-time voice interface to an existing
application backend. Your backend keeps its logic and authorization; VoiceBridge connects it to a
voice runtime through a small, typed HTTP contract. LiveKit Agents for Node.js is the first
runtime. VoiceBridge is an independent project, not affiliated with LiveKit, Inc.

## What's in this release

- **Backend-controlled voice sessions.** The user's speech is transcribed and sent to your backend
  (`POST /v0/turns`). Its reply is spoken verbatim, with no LLM in the loop. Interrupted replies
  stop, and obsolete replies are never spoken.
- **Explicit session authorization.** Your server creates an opaque session and gets a mic-only
  LiveKit token for a fresh random room. The room is bound to the session with compare-and-set.
  The worker verifies the session with your backend (`POST /v0/sessions/start`) before the agent
  joins, and fails closed.
- **Experimental `/v0` wire contract** with JSON Schemas and conformance vectors, so backends can
  be written in any language.
- **A runnable demo:** a fictional help-desk backend, a host token route, a LiveKit worker, and a
  Next.js page with start/end, mute, live status, transcript, and typed questions.
- **Privacy defaults:** `record: false` (no LiveKit Agent Observability upload), no transcript or
  audio persistence in the demo, no transcript text or credentials in logs.

## Packages (workspace only, not on npm)

| Package                        | Purpose                                                      |
| ------------------------------ | ------------------------------------------------------------ |
| `@voicebridge/core`            | Provider-neutral contracts and wire contract v0 (`zod` only) |
| `@voicebridge/livekit-tokens`  | Server-side, least-privilege LiveKit credentials             |
| `@voicebridge/runtime-livekit` | LiveKit Agents adapter, backend-controlled mode              |

## Not in this release

- Agent-controlled mode (an LLM calling registered backend tools). Planned next.
- Instant revocation: a revoked session ends at its next turn.
- Production authentication, durable session storage, and shared rate limiting. These are your
  application's responsibility. The examples use a localhost-only development identity and
  in-memory stores.
- Runtimes other than LiveKit Agents for Node.js.

## Production deployment warnings

Do not deploy the examples as they are. In particular:

- **The development identity (`VB_DEV_AUTH=localhost`) treats every local request as one synthetic
  user. It has several guards, but it can't detect a reverse proxy on the same machine that adds
  no forwarding headers. Never expose it through a proxy, tunnel, or container port mapping.**
- Replace it with your own authenticator, add CSRF protection if you use cookies, use TLS between
  all services, keep credentials in a secrets manager, and use durable, atomic session storage.
- Speech is processed by LiveKit Cloud and third-party STT/TTS providers. Review their data
  handling and your LiveKit Cloud project settings before using real conversations.

## Known issues

- `@livekit/components-react` 2.9.24 (its bundled components-core) rethrows an abnormally ended text stream as an uncaught
  error. A narrow local patch, mirroring the open upstream pull request
  [livekit/components-js#1426](https://github.com/livekit/components-js/pull/1426), is applied at
  install time and will be removed when upstream ships a fix.
- `@livekit/components-react` 2.9.24 quirks are worked around in the demo (token fetching on mount,
  `useAgent` staying `failed` after a reconnect). See the examples README.
- The browser demo was verified end to end with synthetic microphone audio and mocked tests. A real
  microphone and audible playback must be confirmed manually before release (see the
  [manual checklist](v0.1.0-alpha.1-manual-checklist.md)).
- Three moderate `pnpm audit` advisories remain in dependencies (`minimatch` in ESLint tooling,
  `glob` in a build-time transformer bundled with `@livekit/agents`). Neither is reachable with
  untrusted input in VoiceBridge.

## Getting started

See the [quickstart](../../README.md#quickstart-run-the-demo). You need Node.js 24, pnpm 10, a
LiveKit Cloud project, and a browser with a microphone.
